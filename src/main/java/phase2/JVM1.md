# JVM Architecture — Revision Notes

## 1. What is JVM?

JVM stands for Java Virtual Machine.

It is responsible for executing Java bytecode and managing runtime memory.

Java source code:

```java
Main.java
```

Compile:

```powershell
javac Main.java
```

Output:

```text
Main.class
```

Execute:

```powershell
java Main
```

The JVM loads and executes the bytecode.

### Responsibilities of JVM

- Loads class files.
- Verifies bytecode.
- Executes bytecode.
- Manages runtime memory.
- Performs garbage collection.

## 2. JDK vs JRE vs JVM

| Component | Meaning | Purpose |
|---|---|---|
| JDK | Java Development Kit | Develop, compile and run Java |
| JRE | Java Runtime Environment | Provides runtime components |
| JVM | Java Virtual Machine | Executes bytecode |

### JDK

Provides:
- Java compiler (`javac`)
- Java launcher (`java`)
- Runtime components
- Development tools

### JRE

Conceptually provides:
- JVM
- Java class libraries
- Supporting runtime files

### JVM

- Executes Java bytecode.
- Manages runtime memory.
- Supports garbage collection.

**Remember:** JDK includes development tools and runtime components. JRE is the conceptual runtime environment containing the JVM.

Modern JDK distributions do not necessarily provide a separate JRE installation.

## 3. Java Execution Flow

```text
Main.java
    |
    v
Java Compiler (javac)
    |
    v
Main.class
    |
    v
JVM
    |
    v
Class Loading
    |
    v
Bytecode Execution
    |
    v
Program Output
```

### Important Terms

**Source Code:** Java code written by developers.

**Bytecode:** Intermediate instructions generated by the Java compiler and stored in `.class` files.

**Machine Code:** Instructions executed by the computer's processor.

**JIT Compiler:** Compiles frequently executed bytecode into native machine code to improve performance.

## 5. Class Loader Subsystem

### Definition

Class Loader loads Java `.class` files into JVM memory when required.

### Types of Class Loaders

**1. Bootstrap Class Loader**

Loads fundamental Java classes.

Examples:
- String
- Object
- System
- Integer

**2. Platform Class Loader**

Loads platform classes and modules.

In Java 8, it was called the Extension Class Loader.

**3. Application Class Loader**

Loads application classes from the classpath.

### Hierarchy

```text
Bootstrap Class Loader
        |
Platform Class Loader
        |
Application Class Loader
```

### Parent Delegation Model

When a class loader receives a request, it generally delegates the request to its parent first.

Benefits:
- Avoids unnecessary duplicate class loading.
- Protects core Java classes.
- Maintains class-loading consistency.

## 6. Class Loading Lifecycle

Three major stages:

### A. Loading

JVM finds and loads the class definition.

### B. Linking

Linking contains three stages:

**Verification**
- Checks bytecode validity.
- Checks structural correctness.
- Helps ensure bytecode follows JVM rules.

**Preparation**
- Allocates memory for static fields.
- Assigns default values.

Example:

```java
static int count = 10;
```

During preparation:

```text
count = 0
```

**Resolution**
- Converts symbolic references into direct references as required.

### C. Initialization

JVM executes static initializers and assigns explicit static values.

Example:

```java
class Demo {

    static int count = 10;

    static {
        System.out.println("Initialized");
    }
}
```

## 7. Runtime Data Areas

JVM uses different runtime memory areas.

| Memory Area | Shared or Private | Purpose |
|---|---|---|
| Heap | Shared | Objects and arrays |
| Method Area | Shared | Class-level structures |
| Java Stack | Per thread | Method calls and stack frames |
| PC Register | Per thread | Current JVM instruction |
| Native Method Stack | Per thread | Native method execution |

### A. Heap

Stores:
- Objects
- Arrays

Characteristics:
- Shared between threads.
- Managed by garbage collection.
- Objects are allocated here.

Example:

```java
Employee employee = new Employee();
```

The Employee object is allocated on the heap.

### B. Java Stack

Each thread has its own Java Stack.

Stores stack frames created during method execution.

A stack frame contains:
- Local variables
- Operand stack
- Runtime information for the method call

Example:

```java
public class Main {

    public static void main(String[] args) {
        int a = 10;
        calculate();
    }

    static void calculate() {
        int b = 20;
        System.out.println(b);
    }
}
```

Execution:
1. `main()` frame is created.
2. `calculate()` frame is pushed.
3. `calculate()` completes and its frame is popped.
4. `main()` continues and completes.

### C. Method Area

Shared runtime area that stores class-level structures.

Examples:
- Class metadata
- Runtime constant pool
- Method information
- Field information
- Method bytecode

**Java 8 HotSpot detail:** Class metadata is stored in Metaspace, which uses native memory rather than the Java Heap.

### D. PC Register

PC stands for Program Counter.

Each thread has its own PC Register.

It tracks the current JVM instruction being executed by that thread.

### E. Native Method Stack

Used for native method execution, typically involving code written in C or C++.

---

## 8. Execution Engine

Responsible for executing loaded bytecode.

### Interpreter

Executes bytecode instructions one at a time.

### JIT Compiler

Compiles frequently executed code into native machine code for improved performance.

### Garbage Collector

Reclaims heap memory occupied by unreachable objects.

---

## 9. JNI and Native Libraries

JNI = Java Native Interface.

It allows Java code to interact with native code written in languages such as C and C++.

Common uses:
- Operating system interactions.
- Native libraries.
- Hardware-level integration.

## 10. Important Java 8 Details

| Topic | Important Fact |
|---|---|
| String | Bootstrap-loaded class |
| Bootstrap loader | Represented as `null` through `ClassLoader` API |
| Platform loader | Called Extension Class Loader in Java 8 |
| Static field initialization | Default values during preparation; explicit values during initialization |
| Class metadata | Stored in Metaspace in HotSpot Java 8 |
| Heap | Shared among threads |
| Java Stack | Private to each thread |
| PC Register | Private to each thread |
